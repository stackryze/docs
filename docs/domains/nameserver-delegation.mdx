Stackryze Domains operates strictly on an `NS` delegation model. When you register a subdomain, Stackryze writes `NS` records in the authoritative parent zone (`indevs.in.`, `sryze.cc.`, `ryzedns.org.`, `nx.kg.`, or `ryzn.pro.`) pointing resolvers to your chosen nameservers.

You retain full control over DNS records (`A`, `AAAA`, `CNAME`, `MX`, `TXT`, `SRV`, `CAA`) at whichever authoritative DNS provider you point those nameservers to.

## Default nameservers

New registrations are assigned the three Stackryze authoritative nameservers by default:

```dns
yourname.indevs.in.  3600  IN  NS  ns1.stackryze.com.
yourname.indevs.in.  3600  IN  NS  ns2.stackryze.com.
yourname.indevs.in.  3600  IN  NS  ns3.stackryze.com.
```

<Note>
  Assigning default nameservers creates parent delegation, but does not automatically populate records inside `dns.stackryze.com`. To host records on Stackryze DNS, add your subdomain zone at [dns.stackryze.com](https://dns.stackryze.com) and complete ownership verification.
</Note>

## Bringing your own DNS provider (BYOD)

You can replace the default Stackryze nameservers completely with any authoritative DNS provider such as Cloudflare, AWS Route 53, DigitalOcean DNS, Hetzner, or your own PowerDNS server.

When editing nameservers in **My Domains → Manage → DNS Configuration → Edit**:

- **Minimum nameservers:** **2** (`NS1` and `NS2` are required)
- **Maximum nameservers:** **6** (`NS1`–`NS6` supported in the dashboard)
- **Format rules:** Each entry must be a valid public DNS hostname (up to 253 characters), with no protocols (`http://`), IP addresses, `localhost`, `example.com`, or duplicate hostnames.

If you replace `ns1.stackryze.com` and `ns2.stackryze.com` with external provider hostnames (for example `ava.ns.cloudflare.com` and `curt.ns.cloudflare.com`), Stackryze patches the parent zone `NS` RRset (`TTL 3600`) immediately and flags the domain as externally delegated.

## Using Stackryze DNS (`dns.stackryze.com`)

Platform subdomains require a one-time ownership handshake before [dns.stackryze.com](https://dns.stackryze.com) activates the zone:

<Steps>
  <Step title="Add the subdomain zone on Stackryze DNS">
    Open [dns.stackryze.com](https://dns.stackryze.com) and create a zone for your full subdomain (for example `yourname.indevs.in`). Because it belongs to a platform root zone, Stackryze DNS assigns status `pending_ownership` and generates a one-time code starting with `sryze-verify-`.
  </Step>
  <Step title="Save the code on Stackryze Domains">
    Open your domain on [domain.stackryze.com](https://domain.stackryze.com), scroll to **DNS Ownership Verification**, click **Add Code**, and paste the `sryze-verify-...` string.
  </Step>
  <Step title="Verify ownership">
    Return to [dns.stackryze.com](https://dns.stackryze.com) and click **Verify Ownership**. Stackryze DNS validates the code with the Domains registry using a constant-time check, ensures your subdomain delegates to `ns1.stackryze.com`, `ns2.stackryze.com`, and `ns3.stackryze.com`, and moves your zone to `pending_verification`.
  </Step>
  <Step title="Complete NS verification">
    Click **Verify** on Stackryze DNS once delegation resolves so your zone status changes to `active`.
  </Step>
</Steps>

## Propagation timing

Parent zone updates in Stackryze PowerDNS happen immediately on save (`TTL 3600`), while external resolvers pick up changes over time:

```bash
dig NS yourname.indevs.in @ns1.stackryze.com +short
```

Public recursive resolvers usually observe new nameservers within minutes, though ISP caches can retain old `NS` records for up to 48 hours.
